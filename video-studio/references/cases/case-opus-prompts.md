## 2. 一句话结构

先按交付物选技术路线，再复制该路线的提示词结构：不是先选模型或工具，而是先回答“这条片子最终要交付什么”，再决定用 Canvas、Remotion、Manim 还是剪辑。

## 3. 时间轴

本卡是案例集合，不存在成片时间轴。下面的“路线选择表”替代时间轴，按交付物从轻到重排列。

| 交付物 | 技术路线 | 什么时候选 |
|---|---|---|
| 单页轻量动效、像素、HUD | Canvas / JS 单 HTML | 10–30 秒、无需构建、要逐帧可控 |
| 手绘、笔刷、绘本 | p5.js + brush | 需要笔触、纸张和逐笔生长 |
| React 组件化、字幕、批量 | Remotion | 已有 React 能力，需要 Composition 复用 |
| HTML 时间线、模板化 | HyperFrames | 想用 HTML/CSS 快速搭时间线 |
| 数学、公式、教学 | Manim | 需要公式排版和几何推导 |
| 数据、科学可视化、完全可控 | Python 逐帧 | 每帧由数据计算，要求可复现 |
| 3D、粒子、空间 | Three.js / WebGL | 需要真实 3D 空间或 Shader |
| 已有 AE / Blender 工程 | AE / Blender 控制 | 需要高端 3D 或现成工程资产 |
| 口播、二创、已有素材 | 剪辑现有素材 | 不生成画面，只做重排、字幕和包装 |

路线没有绝对优劣：10 秒一次性动效用 Remotion 是过度工程，长片用手写 Canvas 则维护成本过高。

## 4. 视觉语法

- **#17 Pixel Wizard**：128×96 离屏画布、限色盘、整数像素，低分辨率放大后仍保持硬边。
- **#10 Talking head to line art**：保留中文原声和字幕，把 B-roll 替换成线稿，人物与线稿同框。
- **#03 中国五千年线稿**：长卷式线稿加时间轴或地图，单色为主，靠构图推进历史叙事。
- **#12 / #13 Remotion app promos**：真实 UI 组件、弹簧或插值动画，产品界面是主角。
- **#16 高端产品**：暗背景、材质与光、慢镜头，强调质感和克制。
- 其余案例按路线归类；先看缩略图和标题，再决定是否打开完整提示词。

## 5. 动效与转场

- 像素路线：整像素移动、限色盘闪烁、逐帧精灵，不使用运动模糊。
- 线稿路线：线条逐笔画出，已有素材与线稿之间用硬切或遮罩替换。
- Remotion 路线：spring / interpolate 驱动，转场在 Composition 内完成。
- Manim 路线：公式逐项展开、几何图形变换，镜头推近局部。
- 3D 路线：镜头推进、屏幕旋转、景深和反射，避免无目的环绕。
- 通用原则：先定一个主运动，再决定要不要加第二个；转场服务段落，不服务炫技。

## 6. 字幕与声音

- 按案例处理；本卡不提供统一声音模板。
- **#10** 的关键是保留中文原声和字幕，只替换画面，因此切点必须贴原声。
- 口播类路线先做词级时间轴，再做画面绑定。
- 产品类路线通常用音乐加 SFX，字幕只保留卖点短句。
- 教学类路线字幕密度更高，需要提前做中文字号和断行测试。

## 7. 可执行配方

1. **按交付物选路线**
   - 先写清交付物：时长、画幅、是否需要交互、是否需要批量。
   - 对照路线表排除不合适的工具，只留 1–2 个候选。
   - 用最小 demo 验证候选路线，再写完整 brief。
2. **先 storyboard 再写代码**
   - 每个镜头写清时长、画面主体、运动和信息点。
   - 先确认镜头之间的逻辑，再决定每镜用什么技术实现。
   - storyboard 不超过一页，避免把实现细节提前写死。
3. **先渲 4 帧再全量**
   - 选开场、转折、高潮、结尾四个时间点。
   - 检查构图、可读性、层级和品牌色。
   - 4 帧通过后再全量渲染，减少无效等待。

## 8. 失败模式

- **无明确许可**：项目默认保留所有权利，不能直接商用或再分发。解决：只借方法，不复制原文和素材。
- **案例是 demo，不是生产**：缺少错误处理、素材授权、多分辨率和边界情况。解决：把案例当参考，不当交付模板。
- **直接复制提示词水土不服**：模型版本、语言、素材和时长都不同。解决：按自己的 brief 重写门槛和约束。
- **路线选错**：10 秒一次性动效用 Remotion，或长片用手写 Canvas，都会浪费成本。解决：先按交付物选路线。
- **案例编号漂移**：仓库更新后 #17 可能不再是同一个案例。解决：引用标题加链接，编号只作辅助。

## 9. 关键帧与适用场景

- 远程案例，无本地关键帧；需要时先拉取仓库，按路线打开对应案例。
- 优先看 #17、#10、#03、#12/#13、#16，覆盖像素、线稿、历史叙事、产品片和高端质感五类常见需求。
- 适合：项目早期找路线、找参考、写 brief、和客户对齐“要做什么”。
- 不适合：直接复制成生产代码、需要明确商用授权、或需要完整工程脚手架的项目。
- 借用建议：主卡借“交付物 → 路线”的决策顺序；辅卡最多借一个重点案例的视觉语法，不要同时套用多条路线。
