# 案例卡：beat-synced 多版本 showreel（awesome-showreels）

层级：S。风格映射：`08-pixel-arcade`、`16-pixel-jrpg`、`17-pixel-platformer`、`18-pixel-isometric`。本文是远程项目摘要，无本地抽帧。

## 1. 元信息

| 项 | 值 |
|---|---|
| 远程项目 | `awesomezun/awesome-showreels`（GitHub） |
| 许可 | MIT |
| 规模 | 88 个示例；支持 15 / 30 / 60 秒多版本 |
| 像素子风格 | `pixel-isometric`、`pixel-jrpg`、`pixel-platformer`、`pixel-arcade`、`pixel-pocket`、`voxel`、`ascii`、`synthwave` |
| 本地帧 | 无（远程案例，未拉取素材） |
| 适用模式 | 像素 reel、作品集、多版本交付、beat sync |

项目以 showreel 为中心，不是叙事片模板。所有时间信息是流程顺序，不是成片时间码。

## 2. 一句话结构

把“源材料的风格”抽成 `style.json`，再用同一套 beat grid 排 15 / 30 / 60 秒多版本：风格先固化，镜头再按小节填充，最后用音画校验保证每个 cue 都落在拍上。

## 3. 时间轴

| 阶段 | 产出 | 要点 |
|---|---|---|
| 量源 | 素材清单与可用镜头统计 | 决定能剪多长、哪些镜头可重复使用 |
| storyboard | 按 beat 排段落 | 先定每段情绪和镜头，不先写代码 |
| 真实素材 | 选取、裁切、调色 | 不用生成模型伪造不存在的素材 |
| beat grid | 用 `plan_cut.py` 排小节 | 15 / 30 / 60 秒共用一套 cue map |
| 代码场景 | 按 `style.json` 写场景 | 每帧由 t 决定，可局部重渲 |
| 合成音乐 / SFX | score 加音效 | 音乐为主，音效只强调切点 |
| 校验 | 用 `verify_sync.py` 检查 | 音画误差控制在容差内 |
| 输出 | MP4 + HTML | 可编辑、可复现、可派生新版本 |

流程的核心是“先量源、再排 grid、最后写场景”，不是先写代码再找音乐。

## 4. 视觉语法

- 仓库覆盖 88 种风格，按家族可分像素、印刷、3D、插画、UI 和音乐 led 六类。
- 像素子风格之间差异明确，选型时按名称即可判断大致语法。
- **说明**：以下像素语法为通用归纳，非仓库文档原文；复刻前以实际仓库/样片为准。
- 各子风格的通用归纳：
  - `pixel-isometric`：2:1 等距网格、32×16 tile、低饱和底加单一强调色。
  - `pixel-jrpg`：16-bit 回合制、对话框、角色偏小、菜单框明显。
  - `pixel-platformer`：横版卷轴、2–3 层视差、跳跃 squash、整像素滚动。
  - `pixel-arcade`：街机 HUD、高对比、分数与命数、可选扫描线。
  - `pixel-pocket`：掌机小屏、更低分辨率、大像素字、有限色。
  - `voxel`：体素块、等距或斜视角、有限色盘、块状阴影。
  - `ascii`：字符矩阵、终端单色、等宽字体、高对比。
  - `synthwave`：霓虹网格、紫粉青、太阳与山脉剪影、远景横向移动。
- 非像素风格同样以“可复现的代码场景”为前提，不依赖不可控的生成式素材。

## 5. 动效与转场

- `plan_cut.py` 按小节网格排切点，切点优先落在 bar line 或重拍。
- `verify_sync.py` 做音画校验，检查每个 cue 与音频事件是否对齐。
- BPM 范围约 72–176；慢歌用长 bar，快歌用短 bar，不强行统一。
- 15 / 30 / 60 秒版本共用同一套 cue map，只改变镜头密度。
- 转场以硬切、闪白、遮罩和像素擦除为主，不用长溶解拖节奏。
- 同一段素材可以多次出现，但每次要换景别或换运动，避免重复感。

## 6. 字幕与声音

- 可选 Gemini TTS；没有旁白时，音乐承担主要情绪。
- 音乐 ducking：旁白或音效出现时自动压低音乐。
- score 与 SFX 由代码合成或统一管理，保证多版本之间可复现。
- 字幕可选；showreel 以画面和音乐为主，字幕只做标题、作者和联系方式。
- 音效只强调切点和转场，不填满每个空隙。

## 7. 可执行配方

1. **先 `style.json`，再写场景**
   - 从源材料提取色盘、线宽、材质、字体和运动词汇。
   - 把风格参数写进 `style.json`，场景代码只读参数，不硬编码。
   - 先做一个 3 秒测试场景，确认 `style.json` 能复现目标风格。
2. **用 `plan_cut.py` 排 bar grid**
   - 先定 BPM 和小节长度，再标每段的情绪和镜头。
   - 把 15 / 30 / 60 秒版本映射到同一套 cue。
   - 切点先对齐 grid，再微调 ±1–2 帧，不要凭感觉切。
3. **用 `verify_sync.py` 校验 cue**
   - 导出前跑一次音画校验，记录每个 cue 的偏差。
   - 超过容差的 cue 回到 grid 重新排，不靠人耳硬听。
   - 多版本分别校验，避免 60 秒对了、15 秒错位。

## 8. 失败模式

- **showreel 导向，不是叙事片**：没有人物和情节，硬套三幕式会显得空。解决：按情绪和节奏排段落。
- **无中文专项**：字体、断行、标点在像素和 ASCII 风格里容易出错。解决：单独做中文渲染测试。
- **源派生风格需要判断**：抽 `style.json` 时容易过度接近原作。解决：只抽可迁移的参数，不复制具体画面。
- **beat grid 太硬**：口播和对白会被切碎。解决：对白段落改用词级时间轴，不强行卡小节。
- **多版本不是简单拉伸**：把 60 秒加速到 15 秒会丢信息。解决：每个版本重新选镜头和 cue。

## 9. 关键帧与适用场景

- 远程案例，无本地关键帧；需要时先拉取仓库，跑通一个像素子风格再评估。
- 重点看 `pixel-isometric`、`pixel-jrpg`、`pixel-platformer`、`pixel-arcade` 四个子风格，覆盖本库最常见的像素需求。
- 适合：像素 reel、作品集、多版本交付、需要 beat sync 的短节奏片子。
- 不适合：长叙事、口播为主、依赖对白和复杂情节的项目。
- 借用建议：主卡借“`style.json` + beat grid + 多版本”的方法；辅卡最多借一个像素子风格的视觉语法，不要把 88 种风格混在同一条片里。
