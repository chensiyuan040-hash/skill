# 案例卡：产品镜头卡组装（video-shotcraft）

层级：A。风格映射：`01-black-hud-meta`、`05-kinetic-type`、`13-swiss-minimal`。本文是远程项目摘要，无本地抽帧，不复制仓库镜头卡原文。

## 1. 元信息

| 项 | 值 |
|---|---|
| 远程项目 | `Vincentwei1021/video-shotcraft`（GitHub） |
| 许可 | Apache-2.0 |
| 规模 | 13.5k★；124–152 张 shot cards（数量随版本漂移），分 10 类 |
| 排版镜头 | 25 个 typography 镜头 |
| 画幅 / 帧率 | 1920×1080 / 30fps |
| 输出能力 | caption 字幕、SFX 音效库、剪映工程导出 |
| 本地帧 | 无（远程案例，未拉取素材） |
| 适用模式 | 产品宣传片、SaaS 演示、UI 动效、镜头词汇参考 |

镜头卡数量会随仓库更新变化，引用时写“约 124–152 张”，不要当成固定 API 数量。

## 2. 一句话结构

把产品画面拆成一张张可选的镜头卡：先确定要讲的卖点和节奏，再从 10 类卡片里挑镜头、排 storyboard，最后用 Remotion 组装并做帧级 QA，而不是从零手写每个动画。

## 3. 时间轴

制作顺序是“先取素材、再选卡、最后写代码”，时间轴指流程顺序，不是成片时间码。

| 阶段 | 产出 | 要点 |
|---|---|---|
| 1 抓页面 | 产品截图、录屏、UI 状态 | 用真实界面，不用生成模型伪造产品 |
| 2 选卡 | 与卖点匹配的 shot card 清单 | 按信息目的选，不按“看起来炫”选 |
| 3 storyboard | 镜头顺序、时长和转场 | 一镜只承担一个信息点 |
| 4 Remotion 组装 | 可渲染的 Composition | 卡片参数化，文案和素材外置 |
| 5 beat sync / SFX | 切点与音效 | 音乐重拍对齐镜头切换 |
| 6 帧 QA | 关键帧检查清单 | 检查构图、文字和 UI 可读性 |
| 7 输出 MP4 | 成片与可编辑工程 | 同时保留剪映导出的交付路径 |

产品片常见时长 15–60 秒（经验值，非仓库规格），镜头多、单镜短；storyboard 阶段就要决定哪些镜头可以复用。

## 4. 视觉语法

10 类镜头卡覆盖产品片的主要语法：

| 类别 | 用途 |
|---|---|
| 开场 / 品牌 | 建立品牌、产品和情绪基调 |
| 镜头 | 推、拉、摇、移等基础运镜 |
| 转场 | 镜头之间的连接方式 |
| 排版 | 大字标题、金句和字幕强调 |
| UI 入场 | 界面元素逐个出现 |
| 交互 | 点击、悬停、滚动等操作反馈 |
| 数据 | 指标、图表和增长展示 |
| 光 / 强调 | 高光、扫光和局部聚焦 |
| 节奏 | 快切、卡点和节拍镜头 |
| 结尾 | CTA、Logo 和收束 |

- 产品 / UI 电影感：暗背景、真实界面、克制配色，避免模板化七彩渐变。
- 25 个 typography 镜头承担标题、卖点和字幕强调，是产品片里最通用的一组卡。
- 画面主体优先是产品界面本身，装饰元素只做层级和空间，不抢信息。
- 不同类别的卡片可以组合，但一条短片里的镜头语法要统一。

## 5. 动效与转场

- 每张 shot card 自带固定的动效定义和参数入口，调用时只改文案、素材和时长。
- UI 入场以位移、缩放和遮罩为主，模拟真实界面的层级关系。
- typography 镜头用字重、字距和逐字入场制造节奏，不靠复杂粒子。
- 转场优先硬切、推拉和遮罩；产品片不需要长溶解。
- beat sync 让切点落在音乐重拍上，音效只强调关键交互和转场。
- 同一镜头卡连续使用时，至少改变景别、方向或速度其中一项。

## 6. 字幕与声音

- 内置 caption 支持，字幕可以直接挂在镜头卡上，不需要每镜单独写排版。
- 字幕以卖点短句为主，不照搬口播全文；产品片字幕是强调，不是转写。
- 中文需要单独检查字号和断行，仓库文档以英文为主，默认参数不一定适合中文。
- SFX 库覆盖点击、切换、弹出和转场等常见交互声，使用时避免每个动作都配一声。
- 音乐承担节奏，音效只做点缀；旁白出现时音乐要压低。
- 需要后期团队接手时，导出剪映工程比只交 MP4 更实用。

## 7. 可执行配方

1. **先选卡，再写代码**
   - 把卖点拆成 5–8 个信息点，每个信息点匹配 1–2 张候选镜头卡。
   - 在 storyboard 上排好顺序和时长，确认没有重复语法。
   - 只对选中的卡片写参数和素材绑定，不复制整个卡片库。
2. **用 typography 卡做字幕和标题**
   - 标题用大字号 typography 镜头，字幕用较轻的排版卡，避免同一画面两种大字。
   - 中文按语义断行，检查 1920×1080 下的安全区和最小字号。
   - 同一支片里固定 1–2 套字体和字重，不逐镜换字体。
3. **帧 QA 后再交付**
   - 在开场、每个产品功能切换点、结尾各截一帧。
   - 检查 UI 是否可读、文字是否溢出、品牌色是否一致。
   - 帧检查通过后再全量渲染，避免整片渲完才发现版式错误。

## 8. 失败模式

- **没有像素类镜头**：这套面向产品 UI，不是像素动画库。解决：像素需求改用像素引擎，不要强行用 UI 卡模拟。
- **没有口播专用卡**：镜头卡围绕产品画面设计，不处理长口播的词级同步。解决：口播项目另接词级时间轴。
- **英文文档为主**：中文排版、标点和断行缺少现成规范。解决：自建中文样式表和测试帧。
- **产品广告导向**：所有卡片都为卖点服务，做叙事片会显得空。解决：叙事项目换故事板驱动的引擎。
- **卡片数量漂移**：版本更新后卡片编号和数量可能变化。解决：引用卡片名称和用途，不只记编号。
- **堆卡导致节奏过密**：每 1–2 秒换一个镜头，观众看不清产品。解决：一个信息点至少留够读完标题的时间。

## 9. 关键帧与适用场景

- 远程案例，无本地关键帧；需要时先拉取仓库，挑 3 张卡跑一个 10 秒测试。
- 优先看开场 / 品牌、排版、UI 入场三类：它们决定产品片的第一印象和信息可读性。
- 适合：产品宣传片、SaaS 演示、UI 动效、需要快速建立镜头词汇的项目。
- 不适合：像素风、长口播、纯叙事或依赖实拍素材的片子。
- 借用建议：主卡借“10 类镜头卡 + storyboard 组装”的方法；辅卡最多借 typography 或 UI 入场其中一类，避免一条片里混入过多镜头语法。
