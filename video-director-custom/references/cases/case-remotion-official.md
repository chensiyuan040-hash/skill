## 4. 视觉语法

- 画面由 React 组件描述，布局、字体、颜色和动画都是普通前端代码。
- `Composition` 定义时长、分辨率、帧率和默认 props；`Sequence` 负责时间区间内的嵌套。
- 视觉风格不固定：黑底 HUD、产品 UI、排版片都能写，但都要自己实现设计系统。
- 官方最佳实践偏向工程正确性：确定性渲染、可复用组件、props 驱动，而不是提供现成模板。
- 与 `01-black-hud-meta`、`05-kinetic-type`、`13-swiss-minimal` 等风格库配合时，风格卡负责视觉参数，本技能负责 React 实现。
- 本技能不提供像素或手绘专项，视觉语法由项目自己的风格模板决定。

## 5. 动效与转场

- 动效由 `spring()`、`interpolate()` 和帧号驱动，所有状态从 `useCurrentFrame()` 推导。
- 不使用 `Date.now()`、随机数或浏览器当前时间，保证同一帧可重复渲染。
- 转场可以在 Sequence 边界完成，也可以用遮罩、位移和透明度组合实现。
- 官方最佳实践强调动画参数化：时长、阻尼、延迟写成 props，不在组件里写死。
- 复杂动画拆成小组件，每个组件只负责一个运动，便于复用和调试。
- 渲染前先看 Studio 预览，确认帧率和时长，再决定是否全量导出。

## 6. 字幕与声音

- 字幕走 `remotion-captions`：支持导入 SRT、从音频转写、以及常见的字幕显示组件。
- 字幕的字体、字号、描边和断行要按项目语言单独配置。
- 官方技能没有中文（CJK）专项指南；中文换行、标点和字体必须自测。
- 中文测试至少覆盖：长句断行、数字与英文混排、标点避头尾、最小可读字号。
- 音频用 Remotion 的音频组件挂载，旁白与音乐分开控制音量。
- 渲染前确认字幕时间码与音频一致，避免预览正常、导出错位。

## 7. 可执行配方

1. **字幕用 `remotion-captions`**
   - 先确定字幕来源：已有 SRT、外部转写，还是 Remotion 内置转写。
   - 按语言设置字体和断行规则，中文单独做一次溢出测试。
   - 字幕组件只读时间码和文本，不把业务文案写进组件内部。
2. **排版 / 布局用 `remotion-markup`**
   - 先搭静态版式，确认安全区、层级和字号，再加动画。
   - 中文排版优先检查行高、字距和标点，英文规则不能直接套用。
   - 复用组件时用 props 控制内容，不为每条片复制一份组件。
3. **渲染用 `remotion-render`**
   - 先在 Studio 预览，再用低分辨率跑一小段验证。
   - 确认输出帧率、时长和编码参数，再全量渲染。
   - 渲染失败时先看帧号和日志，不要盲目重跑整片。

## 8. 失败模式

- **没有像素 / CJK 专项**：官方技能覆盖通用 React 视频，不覆盖像素美术和中文排版细节。解决：视觉和中文规范由项目风格卡补齐。
- **Remotion 公司许可**：Remotion 本体对商业使用有公司许可要求。解决：商用前核对官方许可条款，不把技能包当成授权。
- **重复安装官方套件**：本机已有完整技能包，再装一份会造成版本冲突和路由混乱。解决：直接引用现有安装，升级走 `remotion-upgrade`。
- **把路由当教程通读**：一次加载全部文档，上下文被无关内容占满。解决：按任务只进一个子技能。
- **非确定性动画**：使用真实时钟或随机数，导致渲染结果不可复现。解决：所有状态从帧号推导。
- **跳过 Studio 预览**：直接全量渲染，错误成本高。解决：先预览关键帧，再小范围试渲。
