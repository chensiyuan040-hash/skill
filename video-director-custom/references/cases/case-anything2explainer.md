# 案例卡：中文讲解流水线（anything2explainer）

层级：S。风格映射：`01-black-hud-meta`、`20-whiteboard-handdrawn`。本文是远程项目摘要，无本地抽帧，不复制仓库提示词或源码。

## 1. 元信息

| 项 | 值 |
|---|---|
| 远程项目 | `Vincentwei1021/anything2explainer`（GitHub） |
| 许可 | PolyForm 非商业许可；商用前必须确认授权或替换实现 |
| 规模 | 2.7k★；201 个文件；随仓库附一条 5 分钟、44 镜头的参考片 |
| 技术栈 | Remotion 4.0.507 + React 19 |
| 画幅 / 帧率 | 1280×720 / 30fps（参考规格，不是交付上限） |
| 中文 TTS | 默认 edge-tts `zh-CN-YunxiNeural` |
| 本地帧 | 无（远程案例，未拉取素材） |
| 适用模式 | 中文讲解、口播、知识视频、批量生产 |

参考片的 5 分钟 / 44 镜头是节奏样本，不是硬性模板；实际时长和镜头数按脚本决定。

## 2. 一句话结构

把中文讲解做成一条可检查的流水线：研究 → 旁白与词级时间轴 → 30 秒 pilot → 并行构建 → QC，每个检查点都先确认上游，再放开下游并行。

## 3. 时间轴

仓库把流程拆成 9 个阶段；下表按交付物归并为 6 组，并标出 4 个检查点。

| 阶段组 | 产出 | 检查点 |
|---|---|---|
| 研究 / 选题 | 事实、结构、目标时长和语言 | 确认时长与语言，避免做完才发现时长不对 |
| 旁白脚本与词级时间轴 | 分句旁白 + 词级时间戳 | 旁白检查：语义、断句、术语是否准确 |
| TTS | 中文配音 | TTS 检查：发音、数字读法、专有名词 |
| 30 秒 pilot | 可看的最小片段 | 前 30 秒检查：钩子、字幕、视觉是否成立 |
| 并行构建 | 各章节画面与字幕 | 只在 pilot 通过后并行，减少集体返工 |
| QC / 交付 | 全片渲染与验收 | 帧级指标和人工抽看 |

顺序的关键是“先 pilot 再并行”：30 秒没跑通就并行，错误会被复制到每个章节。

## 4. 视觉语法

- 黑底 + 白线稿 + 紫色强调，信息层级靠线宽和颜色区分，不靠阴影和材质。
- 星空或点阵背景承担空间感，静止时几乎不可见，运动时才显出层次。
- 章节卡用大字和编号切段，让长讲解有明确的呼吸点。
- 底部常驻进度条，观众随时知道还剩多少内容。
- 线稿优先表达结构关系：箭头、框线、节点和标注，不用写实插画。
- 1280×720 是参考分辨率；复刻到 1080p 时要重排字号、线宽和留白。

## 5. 动效与转场

- 逐帧确定性：任意帧只由当前帧号推导，可以随时跳转和局部重渲。
- 元素入场以线条绘制、位移和淡入为主，避免和字幕抢注意力。
- 章节卡在段落边界出现，停留时间跟旁白句子对齐。
- 进度条连续推进，不按段落跳变，给观众稳定的时间预期。
- 转场以硬切和章节卡为主，少用溶解和花哨擦除。
- 同一画面内的动效不超过两个主动作，第三个动作只做辅助。

## 6. 字幕与声音

- 词级字幕，字号约 44px，配深色描边，保证黑底和星空背景上都可读。
- 中文每块约 16 字，超过就断行，不把一句话挤成两行小字。
- 句与句之间留约 10 帧，段与段之间留约 30 帧，给观众换气。
- 默认 TTS 为 `zh-CN-YunxiNeural`；换音色后要重新做词级对齐。
- 旁白是主声道，音乐只做底；音乐不能盖过中文辅音。
- 字幕断行按语义切，不要把数字、英文缩写或术语拆开。

## 7. 可执行配方

1. **先做 30 秒 pilot，再并行**
   - 选全片最有代表性的一段，覆盖开场、主体和转场。
   - 检查钩子、字幕密度、线稿可读性和音频响度。
   - pilot 通过后才拆章节并行，失败则先改模板再重跑。
2. **中文字幕按 16 字 / 块做预算**
   - 写脚本时按每块约 16 字估算字幕行数。
   - 长句在语义边界断开，不按标点机械切。
   - 字幕完成后在目标分辨率下逐块检查，避免溢出安全区。
3. **用 `frame_metrics.py` 做帧级 QC**
   - 抽查关键帧的亮度、对比度和字幕区域，发现异常再定位到具体帧号。
   - 把指标检查放在人工抽看之前，先排除明显的渲染错误。
   - 指标通过不等于好看，最终仍要按 4 个检查点人工确认。

## 8. 失败模式

- **非商业许可**：PolyForm 非商业许可限制商用和再分发。解决：只借流程和视觉方法，商用项目重写实现或取得授权。
- **仅横屏**：参考实现面向 1280×720 横屏。解决：竖屏要重做布局、字号和安全区，不能直接裁切。
- **原声需手工对齐**：默认流程围绕 TTS，原声输入缺少自动词级对齐。解决：先用外部转写拿到词级时间，再接入时间轴。
- **单一视觉风格**：黑底白线稿紫强调适合讲解，不适合所有题材。解决：把颜色和背景参数化，按项目换皮。
- **直接复用 201 个文件**：工程复杂度高，版本和依赖容易漂移。解决：只抽出需要的 Composition 和组件，按当前 Remotion 版本重建。
- **跳过 pilot**：并行之后才发现节奏或字幕问题，返工面积最大。解决：把 30 秒 pilot 设为硬门槛。

## 9. 关键帧与适用场景

- 远程案例，无本地关键帧；需要时先拉取仓库，按 30 秒 pilot 的范围试跑。
- 重点看：章节卡与进度条如何组织长内容、44px 词级字幕的可读性、pilot 到并行的拆分边界。
- 适合：中文讲解、知识科普、需要稳定字幕规范和批量产能的口播视频。
- 不适合：商用闭源交付、竖屏优先、依赖真实拍摄素材或复杂 3D 的项目。
- 借用建议：主卡借“pilot 闸门 + 16 字字幕预算 + 帧级 QC”；辅卡最多借章节卡或进度条其中一种，不要同时套用整套黑底线稿视觉。
